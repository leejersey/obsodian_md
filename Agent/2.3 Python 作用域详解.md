### **Python 作用域详解：作用域决定了"一个变量在哪里能被访问到"——理解局部、外层、全局、内置这四层 LEGB 查找规则，以及 `global` 与 `nonlocal` 关键字，能帮你避开"变量找不到"和"改了没生效"这两类最常见的坑**

上一节我们学会了如何把值传进函数。这一节要回答一个更底层的问题：**函数里定义的变量，外面能用吗？外面的变量，函数里能改吗？** 这就是"作用域（Scope）"要解决的问题。作用域是初学者最容易感到困惑的概念之一——很多"变量明明定义了却报错""在函数里改了全局变量却没生效"的 bug，根源都在于对作用域理解不清。理解它，你的函数才能写得干净、可控，也才能避免变量之间的意外污染。

### **一、什么是作用域**

**作用域指的是一个变量"有效、可被访问"的代码区域。** 简单说，不是所有变量在任何地方都能用——一个变量能在哪里被读取和使用，取决于它是在哪里被定义的。

最核心的一条规则是：**函数内部定义的变量，默认只在这个函数内部有效，函数一结束就销毁，外部无法访问。**

```python
def my_func():
    x = 10           # x 是函数内部的局部变量
    print(x)         # 10，函数内可以用

my_func()
print(x)             # 报错！NameError：外部访问不到 x
```

这背后的道理是：每次调用函数时，Python 会为它创建一个临时的"命名空间"来存放局部变量，函数执行完这个空间就被清理掉了。这也正是函数能"互不干扰"的原因——不同函数里可以有同名变量而互不影响。

### **二、局部变量与全局变量**

根据定义位置，变量大致分为两类：

- **局部变量（Local）**：在函数**内部**定义的变量，只在该函数内有效。
- **全局变量（Global）**：在函数**外部**、模块顶层定义的变量，整个文件都能访问（包括函数内部可以"读取"它）。

```python
count = 100          # 全局变量

def show():
    msg = "hello"    # 局部变量
    print(count)     # 函数内可以【读取】全局变量 → 100
    print(msg)       # hello

show()
print(count)         # 100
print(msg)           # 报错！局部变量 msg 出不了函数
```

注意这里的关键：**函数内部可以直接"读取"全局变量，但默认不能"修改"它**——这正是下一个要讲的重点。

### **三、最关键的坑：函数内"赋值"会创建新的局部变量**

这是作用域中最容易出错、也最反直觉的地方。看下面的例子：

```python
count = 100

def increase():
    count = count + 1     # 报错！UnboundLocalError
    print(count)

increase()
```

你可能以为它会把全局的 `count` 变成 101，但实际会**报错**。原因是：**只要函数内部对某个变量有"赋值"操作，Python 就会把它整个当作局部变量。** 于是 `count = count + 1` 中右边的 `count` 被认为是"还没赋值的局部变量"，导致报错。

再看一个更隐蔽的版本——"改了却没生效"：

```python
count = 100

def reset():
    count = 0            # 这只是新建了一个局部的 count
    print(count)         # 0

reset()
print(count)             # 100！全局的 count 根本没变
```

这里函数里的 `count = 0` 只是创建了一个**同名的局部变量**，和全局的 `count` 毫无关系。函数结束后它就消失了，全局变量丝毫未变。**牢记：函数内的赋值默认作用在局部，不会影响外部同名的全局变量。**

### **四、global 关键字：在函数内修改全局变量**

如果你**确实想在函数内部修改全局变量**，需要用 `global` 关键字明确声明"我要用的是外面那个全局变量"：

```python
count = 100

def increase():
    global count         # 声明：使用全局的 count
    count = count + 1    # 现在修改的是全局变量
    print(count)         # 101

increase()
print(count)             # 101，全局变量真的变了
```

不过要提醒：**应当谨慎使用 `global`**。滥用全局变量会让程序的数据流变得难以追踪——你很难判断一个全局变量到底在哪些函数里被偷偷改过，这会让 bug 难以排查。**更推荐的做法是通过参数传入、通过 `return` 返回**，让函数的输入输出清晰可见：

```python
def increase(count):
    return count + 1     # 不依赖也不修改全局，干净可控

count = 100
count = increase(count)  # 显式地接收结果
print(count)             # 101
```

### **五、LEGB 规则：Python 查找变量的顺序**

当代码中用到一个变量时，Python 会按一个固定的顺序去四个层级里查找它，这个顺序被称为 **LEGB 规则**：

| 层级 | 含义 | 说明 |
|------|------|------|
| **L**ocal | 局部 | 当前函数内部 |
| **E**nclosing | 外层（嵌套）函数 | 外层的、包裹当前函数的函数 |
| **G**lobal | 全局 | 当前模块（文件）顶层 |
| **B**uilt-in | 内置 | Python 自带的，如 `len`、`print`、`sum` |

查找时**从内到外（L → E → G → B）逐层寻找，找到第一个就停止**，全都找不到才报 `NameError`。

```python
x = "全局"

def outer():
    x = "外层"
    def inner():
        x = "局部"
        print(x)      # 局部（先找到自己的）
    inner()

outer()
print(x)              # 全局
```

如果把 `inner` 里的 `x = "局部"` 删掉，它就会往外层找到 `"外层"`；再把外层的也删掉，就会找到全局的 `"全局"`。这就是 LEGB 逐层向外的过程。

顺带一提：正因为有 Built-in 这一层，你**不要用内置函数名当变量名**，比如写 `list = [1, 2, 3]` 会"遮蔽"内置的 `list`，导致后面无法再用 `list()` 构造列表——这是初学者常犯的隐蔽错误。

### **六、nonlocal 关键字：修改外层函数的变量**

`global` 用于修改全局变量，那如果想在**嵌套函数**里修改**外层函数**（而非全局）的变量呢？这时要用 `nonlocal`：

```python
def counter():
    count = 0                # 外层函数的局部变量
    def increment():
        nonlocal count       # 声明：用的是外层的 count
        count += 1
        return count
    return increment

c = counter()
print(c())    # 1
print(c())    # 2
print(c())    # 3
```

如果不写 `nonlocal`，`count += 1` 又会触发前面讲过的 `UnboundLocalError`。`nonlocal` 常见于**闭包**场景（如上面这个计数器），它让内层函数能够"记住并更新"外层的状态。这属于稍进阶的用法，理解 `global`/`nonlocal` 的对应关系即可：**`global` 找到最外层全局、`nonlocal` 找到最近的外层函数。**

### **七、作用域与可变对象：一个重要的补充**

前面说"函数内不能修改全局变量"，但这个说法有个重要例外需要厘清：**"不能修改"指的是不能重新赋值（改变绑定），但如果全局变量是可变对象（如列表、字典），函数内是可以直接修改其内容的**，因为这不涉及重新赋值：

```python
data = [1, 2, 3]         # 全局的列表（可变对象）

def add_item():
    data.append(4)       # 修改内容，不是重新赋值，无需 global
    print(data)          # [1, 2, 3, 4]

add_item()
print(data)              # [1, 2, 3, 4]，全局列表真的被改了
```

对比之下，`data = [1, 2, 3, 4]`（重新赋值整个列表）就会创建局部变量、需要 `global`。**区分"修改内容"和"重新赋值"是理解这一点的关键**，它也呼应了我们在数据类型那一节讲过的"可变 vs 不可变"。

### **八、AI 开发实战：为什么作用域很重要**

在真实的 AI 应用里，理解作用域能帮你写出更可靠的代码。一个典型的反面教材是滥用全局变量管理状态：

```python
# 不推荐：用全局变量存储对话历史
history = []

def chat(message):
    global history
    history.append(message)
    # ... 调用模型
```

这样写会让 `history` 散落在各处、难以追踪和测试。**更好的做法是把状态封装进类**（呼应我们前面提过、后面会详解的面向对象），或通过参数明确传递：

```python
def chat(message, history):
    """把状态作为参数传入、返回新状态，数据流清晰可控"""
    history = history + [message]
    # ... 调用模型
    return history

conversation = []
conversation = chat("你好", conversation)   # 显式地管理状态
```

原则很简单：**让函数尽量"纯粹"——只依赖它的参数、只通过 return 输出结果，尽量不读写外部的全局状态**。这样的函数好测试、好复用、也不会产生意外的相互影响，是编写健壮 AI 应用的重要习惯。

### **小结与练习建议**

本节的核心记忆点有三个：**函数内部对变量赋值默认创建局部变量，函数结束即销毁，且默认无法修改全局变量（会触发 `UnboundLocalError` 或"改了没生效"）**；**Python 按 LEGB（局部→外层→全局→内置）顺序查找变量，找到即停**；以及 **`global` 用于在函数内修改全局变量、`nonlocal` 用于修改外层函数的变量，但两者都应谨慎使用，优先用参数传入和 `return` 返回来管理数据流**。

建议动手做一个综合练习来巩固：**写一段代码验证作用域——先定义一个全局变量 `total = 0`，写一个函数尝试直接 `total = total + 10` 观察报错，再加上 `global` 让它生效；然后写一个嵌套函数结构，用 `nonlocal` 实现一个累加计数器；最后定义一个全局列表，写一个函数用 `.append()` 修改它、验证无需 `global` 也能改动内容。** 这个练习能一次性覆盖局部/全局、`global`、`nonlocal` 以及可变对象的作用域行为。

掌握了作用域，你就能真正理解"变量在函数内外如何流动"，写出干净无副作用的函数。接下来可以顺利进入"匿名函数 lambda"的学习——它会和作用域中的闭包概念有所关联。如果你希望，我可以针对闭包（closure）的原理，或"变量遮蔽（shadowing）"的更多实战案例再展开深入讲解。
