### **Python 异常处理详解：异常处理是让程序"优雅面对错误"的机制——用 `try/except/else/finally` 捕获并处理运行时错误，而不是让程序直接崩溃，这在调用 API、读写文件、解析数据的 AI 开发中是绝对的刚需**

在前面几节里，我们的代码都默认"一切顺利"。但真实世界充满意外：网络会超时、API 会返回错误、用户会输入乱七八糟的内容、文件可能不存在、JSON 可能解析失败。如果不加处理，任何一个这样的错误都会让程序**当场崩溃并停止运行**。异常处理就是用来解决这个问题的——它让你能预见错误、捕获错误、并决定"出错后该怎么办"。对 AI 应用开发者来说，这几乎是每次调用大模型 API 时都要用到的核心技能。

### **一、什么是异常：错误发生时的"信号"**

当 Python 执行到无法完成的操作时，它会**抛出（raise）一个异常**。如果没人接住这个异常，程序就会终止，并打印一段错误信息（traceback）。先看几个最常见的异常：

```python
print(10 / 0)          # ZeroDivisionError：除以零
print(int("abc"))      # ValueError：无法转换成整数
print([1, 2, 3][10])   # IndexError：索引越界
print({"a": 1}["b"])   # KeyError：字典键不存在
print(undefined_var)   # NameError：变量未定义
```

上面每一行单独执行都会让程序崩溃。异常本身其实是一种**对象**，不同的错误对应不同的异常类型，理解常见类型有助于你精准地捕获它们。下面是 AI 开发中最常遇到的几种：

| 异常类型 | 触发场景 |
|----------|----------|
| `ValueError` | 值不合法，如 `int("abc")` |
| `TypeError` | 类型不匹配，如 `"a" + 1` |
| `KeyError` | 访问字典中不存在的键 |
| `IndexError` | 列表/字符串索引越界 |
| `FileNotFoundError` | 打开的文件不存在 |
| `ZeroDivisionError` | 除以零 |
| `AttributeError` | 访问对象不存在的属性 |
| `TimeoutError` / 网络异常 | API 请求超时或连接失败 |

### **二、基本结构：try / except**

异常处理的核心是 `try / except` 语句。你把**可能出错的代码**放进 `try` 块，把**出错后要执行的补救代码**放进 `except` 块：

```python
try:
    result = 10 / 0
    print(result)
except ZeroDivisionError:
    print("不能除以零")     # 出错后执行这里，程序继续运行
print("程序继续往下走")     # 不会崩溃，正常执行
```

它的执行逻辑是：Python 尝试运行 `try` 块，如果一切正常，就跳过 `except`；如果 `try` 块中**任何一行**抛出了匹配的异常，就**立即跳转**到对应的 `except` 块执行，而 `try` 块中剩下的代码不再执行。

### **三、捕获具体异常 vs 捕获所有异常**

一个非常重要的原则：**尽量捕获具体的异常类型，而不是笼统地捕获所有异常。**

#### **1. 精确捕获（推荐）**

```python
try:
    age = int(input("请输入年龄："))
except ValueError:
    print("请输入有效的数字")
```

#### **2. 捕获多种异常**

可以用一个元组同时捕获多种，或用多个 `except` 分别处理：

```python
try:
    data = {"name": "小明"}
    print(data["age"])          # KeyError
    print(10 / 0)               # ZeroDivisionError
except KeyError:
    print("缺少字段")
except ZeroDivisionError:
    print("除零错误")
except (TypeError, ValueError):   # 元组：多种异常同样处理
    print("类型或值错误")
```

多个 `except` 会从上往下匹配，命中第一个就执行，因此**要把更具体的异常写在前面**。

#### **3. 获取异常信息**

用 `as` 拿到异常对象，可以打印具体的错误内容，这在调试和记录日志时非常有用：

```python
try:
    result = int("hello")
except ValueError as e:
    print(f"出错了：{e}")       # 出错了：invalid literal for int()...
```

#### **4. 关于"捕获所有异常"的警告**

写 `except:` 或 `except Exception:` 能捕获几乎所有异常，看起来省事，但**强烈不推荐滥用**——它会把你意料之外的 bug（比如拼写错误导致的 `NameError`）也一起"吞掉"，让问题变得极难排查。如果确实要用兜底，至少要打印出错误信息：

```python
try:
    risky_operation()
except Exception as e:
    print(f"发生未预期的错误：{type(e).__name__}: {e}")
```

### **四、完整结构：else 与 finally**

`try` 语句还有两个可选的子句，构成完整形态：

```python
try:
    # 可能出错的代码
except SomeError:
    # 出错时执行
else:
    # try 成功、没有异常时才执行
finally:
    # 无论如何都会执行（不管有没有出错）
```

- **`else`**：只有当 `try` 块**没有发生任何异常**时才执行。它的作用是把"正常逻辑"和"可能出错的逻辑"分开，让代码更清晰。
- **`finally`**：**无论是否发生异常，都一定会执行**，常用于"清理工作"，比如关闭文件、释放连接、无论成败都要记录日志。

```python
try:
    f = open("data.txt")
    content = f.read()
except FileNotFoundError:
    print("文件不存在")
else:
    print(f"读取成功，共 {len(content)} 个字符")   # 只有读成功才执行
finally:
    print("操作结束")     # 无论成败都会打印
```

### **五、主动抛出异常：raise**

除了被动捕获，你也可以在代码中**主动抛出异常**，用于"当某个条件不满足时，明确地报错"。这在编写函数、校验参数时很常用：

```python
def set_temperature(value: float):
    if not 0 <= value <= 2:
        raise ValueError(f"temperature 必须在 0~2 之间，收到的是 {value}")
    print(f"温度设置为 {value}")

set_temperature(1.0)     # 正常
set_temperature(5.0)     # 抛出 ValueError
```

主动抛异常比默默返回一个错误值（如 `None`）更好，因为它**强制调用方正视问题**，不会让错误悄悄传播下去。

你还可以在 `except` 中重新抛出异常（先记录日志再往上抛），用 `raise` 不带参数即可原样抛出当前异常：

```python
try:
    risky()
except Exception as e:
    print(f"记录错误日志：{e}")
    raise                    # 记录后重新抛出，交给上层处理
```

### **六、AI 开发实战：一个健壮的 API 调用**

现在把本节知识综合起来，看一个非常贴近真实场景的例子——**带异常处理和重试的大模型 API 调用**。这几乎是每个 AI 应用都会写的代码模式：

```python
import json

def call_llm(prompt: str, max_retries: int = 3) -> dict:
    for attempt in range(1, max_retries + 1):
        try:
            # 模拟调用 API（真实场景是 requests.post(...)）
            response = fake_api_request(prompt)
            data = json.loads(response)        # 可能抛 JSONDecodeError
            reply = data["choices"][0]["text"] # 可能抛 KeyError / IndexError
        except json.JSONDecodeError:
            print(f"第 {attempt} 次：返回内容不是合法 JSON")
        except (KeyError, IndexError):
            print(f"第 {attempt} 次：返回结构不符合预期")
        except TimeoutError:
            print(f"第 {attempt} 次：请求超时，准备重试")
        else:
            # 只有全部成功才走到这里
            print("调用成功")
            return {"success": True, "reply": reply}
        finally:
            print(f"—— 第 {attempt} 次尝试结束 ——")

    # 循环跑完仍未成功
    return {"success": False, "reply": None}
```

这段代码把本节几乎所有要点都用上了：`for` + `try` 实现重试、多个 `except` 分类处理不同错误、`else` 放置成功逻辑、`finally` 做每次的收尾记录。它体现了健壮的 AI 应用应有的样子——**任何一个环节出错，程序都不会崩溃，而是有对应的应对策略**。注意其中 `json.JSONDecodeError` 正好衔接了你下一阶段要学的 `json` 库。

### **七、几条实用的最佳实践**

在结束本节前，总结几条能立刻提升代码质量的原则：

- **只捕获你能处理的异常**。捕获后要么补救、要么记录、要么重新抛出，不要"捕获后什么都不做"（`except: pass` 是最危险的反模式，会让 bug 无声无息地消失）。
- **让 try 块尽量小**。只把真正可能出错的那几行放进 `try`，而不是把一大段代码全塞进去，这样才能精准定位是哪一步出的错。
- **优先在边界处处理异常**，比如所有与外部交互的地方——网络请求、文件读写、用户输入、数据解析，这些正是 AI 应用中最容易出错的环节。
- **用 finally 或上下文管理器（`with`）做资源清理**。事实上，读写文件时更推荐用 `with open(...) as f:`，它会自动关闭文件，无需手动写 `finally`。

### **小结与练习建议**

本节的核心记忆点有三个：**`try` 放可能出错的代码、`except` 接具体的异常类型、`else` 放成功逻辑、`finally` 放必定执行的清理**；**优先精确捕获而非笼统捕获，绝不写 `except: pass` 吞掉错误**；以及 **`raise` 用于主动报错、强制问题暴露出来**。异常处理的本质不是"消灭错误"，而是"预见并优雅地应对错误"。

建议动手做一个综合练习来巩固：**写一个安全的除法函数 `safe_divide(a, b)`——它接收两个用户输入的字符串，尝试转成数字并相除；如果输入不是数字就捕获 `ValueError` 并提示，如果除数为零就捕获 `ZeroDivisionError` 并提示，计算成功则用 `else` 返回结果，最后用 `finally` 打印一句"计算已结束"。** 这个练习能一次性用到 `try/except/else/finally`、多种异常类型和类型转换，非常适合检验本节的掌握程度。
